# Обновление цитат на действующем flood

В репозиторий перенесены серверные изменения анкет с двумя фото, чек-листов,
контактов в личке и интеграции с трекером. Они сверены по Git blob-хешам с
выводом сервера от 07.11.2026. Поверх них добавлены антивалыны, исправления
ФИО/исторических аватарок, медиа-цитаты и сборка цепочек.

## Использование

- `!цитата` ответом: текст, фото, видео, GIF, кружок (квадратное видео со звуком).
- `/цитата` или `/quote` ответом: ветка до корневого сообщения. Если начало
  неизвестно, сохранить доступный фрагмент можно только после подтверждения.
- В личке `/цитата` без ответа: переслать сообщения в нужном порядке и нажать
  «Собрать цитату». Корневой автор подписывает всю цитату. Длинный текст и
  подписи медиа разбиваются на карточки. Сохранённые цитаты общие для мудростей.
- `!мудрость` показывает всю цитату; топ и батл — превью с кнопкой просмотра.
- `!антивалыны` показывает десять наименьших значений, включая отрицательные.

Бот должен видеть обычные сообщения группы (администратор или отключённый
privacy mode). Журнал новых групповых сообщений/правок хранится 90 дней;
старую историю Telegram бот не скачивает. Личные сообщения вне ручной сборки
не архивируются. До 100 частей, 32К текста, 20 МиБ и 60 секунд на вложение,
видео до 4K по числу пикселей. Один worker и очередь SQLite, Redis не нужен.
Исходники медиа временные; результаты переиспользуются по Telegram file_id.
Очередь возобновляется после перезапуска. При аварии между отправкой части
в Telegram и записью ответа возможен повтор последней части.

Историческое фото выбирается по времени снимка (UTC) и дате цитаты (Москва).
Текущее фото не подставляется вместо неизвестного исторического. Для старого
ника `meowwwow66` подтверждена подпись «Диана Зарубина». ФИО ищется при показе.

## Подготовка сервера

Подтверждены контейнер `flood-bot-1`, папка `/root/flood`, compose
`/root/flood/docker-compose.yml`, база `/app/database/bot.db`, смонтированная
из `/root/flood/database`. Трекер и его контейнеры обновлять не требуется.
GitHub Actions для автоматического деплоя в этом репозитории не настроены.

Перед обновлением сделать согласованную копию базы через sqlite3.Connection.backup
и проверить её PRAGMA integrity_check. Уже проверенная копия от 07.11:
`database/bot.db.bak_before_media_20261107_203030_253363` (2 928 640 байт).
Если после неё прошло много времени/появились новые данные, сделать свежую.

Сервер на ветке main, исходный HEAD — `282d5a3`. Рабочие Python-файлы содержат
правки, уже включённые в первый коммит переноса. Перед pull сохранить именно
эти 12 файлов в stash (включая шесть untracked). Базу, .env и аватарки не трогать:

```sh
cd /root/flood
git stash push --include-untracked -m server-code-before-quotes -- database/profile_dao.py database/profile_models.py handlers/command_durak.py handlers/command_help.py handlers/command_profile.py main.py database/checklist_dao.py database/checklist_models.py database/contact_models.py handlers/command_checklist.py handlers/command_tracker.py middlewares/dm_contacts.py
git stash list -1
git status --short --branch
```

После этого могут остаться только изменённые отслеживаемые __pycache__ (они
не используются как исходники и в обновлении не изменяются). Если остались
другие исходники или stash не создался, сначала разобраться, не продолжать.

```sh
git pull --ff-only origin main
git log -3 --oneline
docker compose config --quiet
docker compose up -d --build bot
docker compose ps
docker compose logs --tail=50 bot
```

Stash автоматически не применять: те же изменения уже включены в новый код.
Сохранить stash как дополнительную страховку. Не использовать reset --hard,
git clean или восстановление старой базы поверх новых данных. Дополнительные
таблицы создаются автоматически. Контейнер использует прежние .env/volume,
другой polling-процесс с тем же токеном запускать нельзя.

## Проверка и откат

Проверить анкету, чек-листы и вход в трекер; затем медиа каждого типа,
новую цепочку из ответов, неполную старую цепочку и ручную сборку в личке.
Проверить мудрость, топ/батл, ФИО Дианы и антивалыны.

Перенос состоит из двух коммитов: сначала серверные правки, затем функции
цитат. Для отката новых функций отменяется второй коммит через git revert;
серверная интеграция остаётся. Рабочую базу и новые таблицы не удалять.
После revert/push обновить main и повторить сборку bot. Если после этих
коммитов были другие изменения, предварительно проверить совместимость отката.

Локально: `PYTHONPATH=. python -m unittest discover -s tests -v`.
Нужны зависимости бота и ffmpeg/ffprobe; тесты не обращаются к Telegram.
